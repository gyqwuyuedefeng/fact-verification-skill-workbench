# 现场测试执行卡

这张执行卡只回答三个问题：测试文件在哪里、对话框输入什么、按什么顺序看结果。

## 一、数据分成两组

### 1. 对话页演示材料

以下材料需要在“对话核验”页面手工上传；现场时间有限时先走前三项，完整格式复验再走 Word/PDF/PPT/Excel：

| 文件 | 演示重点 | 正确预期 |
|---|---|---|
| `../demo-materials/01-模拟星河智造经营简报.md` | Markdown、多类型主张、01/02/03 实时过程 | 虚构主体，不能把附件自证为真，应为证据不足 |
| `../demo-materials/02-同名主体核验.txt` | TXT、主体歧义、人工介入 | 主体无法唯一定位时停止后续拼接 |
| `../demo-materials/03-模拟企业经营指标.csv` | CSV、表格定位、年份与万元单位 | 能解析表格，但虚构主体的外部事实仍应证据不足 |
| `../demo-materials/04-影子灰度-科大讯飞经营事实.md` | Stable 正式答案与后台 Candidate 影子 | 正式卡片只显示 Stable；管理页出现一条影子记录，可人工 PASS |
| `../demo-materials/05-影子灰度-金山办公风险事实.md` | 否定性风险和人工 FAIL 按钮 | 覆盖不足应证据不足；FAIL 只表示人工观察，不计算准确率 |
| `../demo-materials/06-模拟企业尽调材料.docx` / `.pdf` | Word 段落与 PDF 页码定位 | 两种格式都能解析，虚构主体不能由附件自证 |
| `../demo-materials/07-模拟企业融资说明.pptx` | PPT 多页与 slide 定位 | 第二页主张带幻灯片位置，外部事实为证据不足 |
| `../demo-materials/08-模拟企业财务台账.xlsx` | Excel 单元格、单位与公式 | 保留工作表/单元格/公式，外部事实为证据不足 |

### 2. 管理评测金标

- 数据文件：`../dataset.jsonl`
- 数据集清单：`../manifest.json`
- 固定版本：`public-tech-2024-v3`
- 样本数量：30 条
- 企业范围：科大讯飞、金山办公、深信服、浪潮信息、用友网络
- 类型分布：基本资料 6、财务 9、知识产权 5、风险 5、关系 5
- 金标分布：`VERIFIED` 20、`CONFLICT` 3、`INSUFFICIENT` 7

`v1` 曾误把股票代码写入内部 `companyId`；`v2` 虽纠正了主体编码，但支持性金标仍引用 Agent
运行时不可见的年报记录。两版均已作为历史缺陷样本归档；`v3` 同时锁定真实内部编码和 MCP
可返回的 ES `recordId`，正式演示只使用 `v3`。

这组数据不上传到对话框。管理员在“管理评测”页选择数据集后，系统自动按固定顺序运行。

## 二、马上能测：推荐顺序

### 第 1 条：确定性财务冲突

运行方式选择 `BASELINE`，复制：

```text
请核验以下企业材料中的财务主张，必须对齐主体、年度、指标口径和金额单位：

科大讯飞股份有限公司 2020 年营业收入为 100 亿元。
```

重点观察：

1. `01 材料解析` 显示文本已解析和待核验主张。
2. `02 执行轨迹` 显示主体搜索、财务工具调用和完成状态。
3. `03 核验主张` 显示 `CONFLICT`，并展示外部财务证据；当前工具记录约为 130.2466 亿元，不能把 100 亿元判为已核实。

### 第 2 条：多主张文本

仍选择 `BASELINE`，复制：

```text
请逐条核验以下材料中的明确企业事实，只能使用企业证据工具，不要使用模型记忆：

科大讯飞股份有限公司统一社会信用代码为 91340000711771143J。
科大讯飞股份有限公司 2024 年营业收入为 23343093018.69 元。
科大讯飞股份有限公司 2024 年不存在任何行政处罚。
```

重点观察：系统应逐条输出结论；特别是“无任何行政处罚”属于否定性主张，查询为空也不能直接判真，覆盖范围不足时应为 `INSUFFICIENT` 并提示人工介入。

### 第 3 条：Markdown 上传

上传 `01-模拟星河智造经营简报.md`，复制：

```text
请逐条核验附件中的工商、财务、知识产权、风险和股权关系主张。
查不到外部记录时必须输出证据不足，不得把附件自身内容当作外部证据。
```

重点观察：Markdown 能被解析成多个主张；虚构企业应为证据不足。

### 第 4 条：TXT 上传

上传 `02-同名主体核验.txt`，复制：

```text
请先确认附件中的企业主体能否唯一定位。
如果名称、统一社会信用代码或注册地址不能对应同一主体，停止后续财务、专利和风险查询，并要求人工确认。
```

重点观察：主体歧义触发人工介入，不能自动取第一个同名企业。

### 第 5 条：CSV 上传

上传 `03-模拟企业经营指标.csv`，复制：

```text
请重点核验附件最后一行的三项主张。
保留年份、万元单位和表格单元格位置；比较营业收入时，将 15100 万元统一换算为 1.51 亿元。
```

重点观察：显示 2025 年、列名、单元格位置和单位换算；虚构主体仍不能由附件自证。

### 第 6 条：完整文件格式

依次上传 `06` 的 Word/PDF、`07` 的 PPT 和 `08` 的 Excel，分别复制 `prompts.md` 场景 8—10。

重点观察：Word 保留段落、PDF 保留页码、PPT 保留幻灯片、Excel 保留工作表/单元格/公式；四份材料均为虚构主体，不能由附件自证。

## 三、完整比赛演示：推荐顺序

1. 在“Skill 实验室”从内置初始规则创建 DRAFT，保存并冻结成首个 Candidate。
2. 在“管理评测”勾选“首次建立 Stable”，填入 Candidate ID，运行 `BASELINE + Candidate` 的 30 条同条件评测。
3. 查看四项核心指标、失败样本、数据集 hash 和版本卡；门禁通过后把首个 Candidate 建立为 Stable。
4. 从 Stable 克隆第二个 DRAFT，仅修改一条明确规则，例如“否定性风险主张不能因为空结果直接判真”，冻结成新 Candidate。
5. 运行 `BASELINE + Stable + Candidate`，查看当前批次、历史批次、一个版本的多次评测汇总，以及 Candidate 相对 Stable 的直接对比。
6. 在 Skill 实验室点击“生成升级描述”，让模型读取两个冻结 Skill，解释真实规则差异。
7. 在“发布管理”注册门禁通过的 Candidate 并开启影子；随后从对话页以 `Stable` 提交一条真实任务。
8. 回到发布页查看同一输入的 PRIMARY/SHADOW 对照，人工标记 PASS 后晋升。
9. 再提交一条新任务证明新 Stable 生效，最后执行回滚并验证后续任务恢复旧 Stable。

自动复验时不要把历史诊断批次当正式成绩。只有 Run Manifest 含固定模型参数、状态为 `COMPLETED` 且页面显示 `GATE PASS` 的 v3 批次可以注册或导出为比赛报告。

## 四、演示时的解释口径

- `BASELINE`：公司同一个千问模型，不加载专用 Skill。
- `Stable`：当前正式 Skill，普通用户可主动选择，结果直接返回给用户。
- `Candidate`：只在管理员离线评测或影子运行中出现，普通用户不可选择、也看不到其结果。
- 同条件评测固定数据、输入、模型、工具、证据快照和参数；当前公司模型还显式固定 `enableThinking=false`、`maxTokens=8192`，唯一变化是是否加载某个冻结 Skill。
- 影子不是让一部分用户偷偷收到 Candidate 答案，而是后台复制 Stable 请求做对照；用户正式答案始终来自 Stable。
