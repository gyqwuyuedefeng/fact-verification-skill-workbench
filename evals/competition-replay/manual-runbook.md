# 手工复演清单

开始前打开 `http://127.0.0.1:15173`，确认管理员导航可见“演示数据”“管理评测”
“Skill 版本”“影子与发布”。现场只选择下面一条路径，不把固定 fixture 当成真实运行结果。
所有版本和评测关联都通过页面下拉框完成，不从地址栏或接口响应手工复制标识。
若启动前只读检查发现“RUNNING 任务 + 超过一小时且从未 started 的 PENDING PRIMARY”这一种遗留模式，
只能由测试运维人员通过 test-only 固定恢复接口处理并重新确认三类活动计数为 `0`；现场页面不手工填写任务或运行标识。

## 路径一：从零真实运行

- [ ] 打开“演示数据管理”，查看“当前演示数据状态”；确认无活动核验或评测后，点击“清空并从第 1 步开始”，精确输入“清空全部比赛数据”。预期七张业务表均为 `0`，三个受管目录均显示“为空”。
- [ ] 打开“Skill 版本实验室”，点击“新建初始草稿（DRAFT）”，在“加载预置内容（仅本地编辑器）”选择“初始稳定版 · 阶段一：稳定基线”，点击“加载到本地”“保存草稿（DRAFT）”“冻结为候选版（CANDIDATE）”。预期版本状态为“候选版（CANDIDATE）”。
- [ ] 打开“管理评测”，在“候选版（CANDIDATE）版本”下拉框选择刚冻结的版本，运行首次基线与候选版评测。预期运行状态依次为“待处理（PENDING）”“运行中（RUNNING）”“已完成（COMPLETED）”，并显示准确率、任务完成率、稳定性、人工介入率。
- [ ] 打开“影子与发布”，分别使用“候选版（CANDIDATE）”和“已通过门禁的评测”下拉框，点击“注册候选版（CANDIDATE）”，按页面流程建立初始“稳定版（STABLE）”。
- [ ] 回到“Skill 版本实验室”，选择稳定版后点击“从已选版本克隆草稿（DRAFT）”，加载“优化候选版 · 阶段二：优化候选”，保存并冻结。预期出现新的“候选版（CANDIDATE）”，原稳定版仍保留。
- [ ] 在“管理评测”用“稳定版（STABLE）版本”和“候选版（CANDIDATE）版本”两个下拉框运行三版本评测。预期按钮显示运行“基线（BASELINE） + 稳定版（STABLE） + 候选版（CANDIDATE）”，完成后门禁为“通过（PASS）”。
- [ ] 在“影子与发布”用两个下拉框关联候选版和通过的评测，点击“注册候选版（CANDIDATE）”“开启影子”。
- [ ] 在“事实核验对话”选择“稳定版（STABLE）”提交一份已授权材料；回到“影子与发布”，在“真实材料影子观察”点击“人工通过（PASS）”。预期正式结果仍来自稳定版，后台出现候选版观察结果。
- [ ] 点击“晋升稳定版（STABLE）”，用新任务确认后续请求读取新稳定版；再点击“回滚上一版”。预期发布历史追加“晋升稳定版（PROMOTE）”和“回滚上一版（ROLLBACK）”，历史任务不被改写。
- [ ] 另建草稿并加载“回归失败版 · 阶段三：门禁失败”，保存、冻结并评测。预期“管理评测”显示“门禁未通过（FAIL）”；不得继续注册或晋升。这是 Preset `03-regression` 的失败证明。

## 路径二：导入内置固定脱敏状态

- [ ] 打开“演示数据管理”，确认七张业务表和三个受管目录均为空；点击“导入固定脱敏内置状态”并确认提示。
- [ ] 预期页面提示“固定脱敏数据，不是本次现场重新生成”；该导入不调用模型。
- [ ] 打开“Skill 版本实验室”，预期版本历史有四条记录，包含稳定版、已归档版本、候选版和草稿。
- [ ] 打开“管理评测”，使用“评测批次”“按版本汇总”“版本对比”切换查看三次固定评测；预期同时包含“通过（PASS）”与“未通过（FAIL）”门禁证明。
- [ ] 打开“影子与发布”，预期“真实材料影子观察”同时包含“人工通过（PASS）”和“人工未通过（FAIL）”，发布历史保留初始化、注册、影子、晋升和回滚记录。
- [ ] 讲解时明确：这些结果只用于快速查看完整状态，不是本次现场重新生成，不能作为真实模型现场运行证据。

## 两条路径共用的页面检查

- [ ] “事实核验对话”中的 01 材料解析、02 执行轨迹、03 核验主张均显示中文状态；普通用户不看到候选版或影子结果。
- [ ] Markdown、TXT、CSV、Word、PDF、PPT、Excel 均可解析，定位信息与文件结构一致。
- [ ] “管理评测”显示同条件锁、四项中文指标、失败样本、Run Manifest 和 Markdown/JSON 报告入口。
- [ ] 影子不是把候选版答案返回给用户，而是后台复制同一输入比较；人工通过只用于晋升门禁，影子真实材料不计算准确率。

## 影子观察记录如何真实产生

1. “影子与发布”必须已经显示一个已注册的候选版（CANDIDATE），再点击“开启影子”，页面状态变为“影子已开启（SHADOW ON）”。
2. 打开“事实核验对话”，运行方式必须选择“当前 Stable”，输入文字或上传授权材料并发送。普通用户页面没有 Candidate 或影子开关。
3. 系统先把同一任务的文档快照、证据快照、模型参数和工具合同锁定；PRIMARY 使用 Stable，是唯一返回给普通用户的正式结果。
4. PRIMARY 完成后，系统自动启动 SHADOW，使用 Candidate 处理同一份输入和同一证据快照。Candidate 失败不会改写正式结果。
5. 回到“影子与发布”的“真实材料影子观察”，刷新后可看到这条任务的 Stable/Candidate 版本、主张一致数和差异数；完成后由管理员选择“人工通过（PASS）”或“人工未通过（FAIL）”。
6. 选择 BASELINE、影子未开启、没有已注册 Candidate，或者任务是开启影子之前创建的，都不会新增影子观察记录。

导入固定脱敏内置状态后页面已有的两条影子记录是固定历史 fixture，用于快速讲解 PASS/FAIL 和发布历史；它们不是本次现场核验产生的数据。现场要证明真实链路，应先记住当前记录数，再按以上步骤提交一条新的 Stable 任务，确认总任务数增加一条。
