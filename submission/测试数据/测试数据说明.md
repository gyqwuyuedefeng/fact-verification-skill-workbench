# 测试数据说明

## 30 条正式金标

- 文件：`dataset.jsonl`
- 清单：`manifest.json`
- 版本：`public-tech-2024-v3`
- 样本数：30
- 用途：Baseline、Stable、Candidate 的可复现同条件评价
- 输出金标：已核实、存在冲突、证据不足

每条 JSONL 包含材料主张、期望主体、规范化指标/期间/单位、期望状态、证据请求和人工核对的证据定位。数据集只保存必要的规范事实、工具名、`recordId` 和定位，不分发企业 ES 原始索引全文。

## 真实企业材料

- `新闻数据原始汇总.txt`：参赛人从公开网络下载整理的原始待核验主张汇总，原文件未附完整来源 URL。
- `真实企业材料节选.txt`：从原始汇总中选取的两条同花顺主张，用于测试同一品牌下不同法律主体、不同年份和证据时效性。

这两份文件只表示“材料里写了什么”，不是权威证据，也没有人工标注金标准。Agent 必须通过企业证据工具核验；如果当前证据库不覆盖 2025—2026 年，应输出证据不足，不能利用模型记忆判真。

## 固定脱敏内置状态

固定内置状态不包含在本测试数据目录中，由应用 test profile 内置 fixture 提供。它导入四个 Skill 状态、三个评测结果、两条影子任务和五步发布历史，不调用模型，仅用于快速查看产品闭环。

## 使用边界

- 正式评价结果必须来自 30 条金标和 Run Manifest。
- 新闻材料不能计入准确率，除非后续补充独立金标和权威证据定位。
- 文件仅用于内部比赛和获授权的演示，不得据此形成对企业的外部评价或自动决策。
