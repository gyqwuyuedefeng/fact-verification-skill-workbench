# 10分钟答辩简短讲稿

## 只记这一条主线

发现通用模型不可靠 → 用 Skill 和 MCP 约束 → 同条件评测证明有效 → 影子灰度安全发布 → 沉淀为火石智能体通用能力。

## 第1页：封面（0:00—0:20）

> 大家好，我们是火石验真官。我们做了一个企业材料事实核验 Agent，能够读取材料、查询企业数据并给出可追溯结论，同时支持 Skill 评测、灰度发布和回滚。

## 第2页：业务问题（0:20—1:10）

> 企业材料里有大量工商、财务、知识产权和风险事实。人工逐条查库很慢，直接问通用模型又可能猜主体、用模型记忆回答，而且结果无法追溯。

> 所以我们选择了一个标准很明确的任务：材料里的事实到底是真的、冲突的，还是证据不足。

## 第3页：解决方案（1:10—2:10）

> 系统先解析文本或文件，由 Agent 提取主张，再通过六个只读 MCP 工具查询企业证据，最后只输出三类结论：已验证、存在冲突、证据不足。

> Skill 负责约束核验规则，MCP 负责提供外部事实，所有结论都保留原文位置和证据记录。

## 第4页：现场演示（2:10—6:10）

操作顺序：

1. 打开“事实核验对话”，选择“当前 Stable”。
2. 输入：`浙江核新同花顺网络信息股份有限公司（300033.SZ）2025年全年实现营业收入60.29亿元。`
3. 展示 `01 输入快照`：说明系统固定了原始材料和位置。
4. 展示 `02 执行轨迹`：说明 Agent 正在调用模型和企业证据工具。
5. 展示 `03 核验主张`：说明结论、解释和证据 recordId 都可追溯。

只需要说：

> 普通用户只使用正式 Stable。系统把输入、工具调用、证据和结论完整保留下来，不是让模型凭记忆直接回答。

如果运行超过20秒：

> 当前正在真实调用公司模型和 MCP。为了控制时间，我切换到已经持久化的正式评测结果。

## 第5页：同条件评测（6:10—7:20）

> 我们固定同一套30条金标准、同一公司千问模型、同一参数、工具和证据快照，唯一变量是加载哪个 Skill。

> 通用基线答对7条，初始 Skill 答对27条，优化 Skill 答对30条，也就是 `7/30 → 27/30 → 30/30`。四项核心指标和八项发布门禁都保留了可复现记录。

## 第6页：安全发布（7:20—8:20）

> Skill 不是一段临时提示词，每个冻结版本都有内容哈希、版本卡和评测绑定。

> Candidate 开启影子后，用户仍然只收到 Stable；Candidate 在后台使用相同输入运行，管理员比较差异并人工确认，之后才能晋升。发现问题可以立即停止影子或回滚上一版。

## 第7页：30天落地（8:20—9:40）

> 当前火石智能体已经具备模型、Agent 和 MCP 能力，但还缺少通用的 Skill 版本、评测、影子和回滚治理。

> 赛后30天，我们计划把本次验证过的能力沉淀到现有火石智能体体系，并再接入一个不同业务目标的 Skill，证明它不是事实核验的专用功能。

结束语：

> 这个作品的价值不是模型回答了一次，而是让 AI 能力可以被验证、被安全发布，也可以在出现问题时回滚。谢谢大家。

## 最后只记5个数字

- `30`：正式金标准样本数。
- `7 → 27 → 30`：三个版本答对数量。
- `4`：准确率、完成率、稳定性、人工介入率。
- `8`：发布门禁数量。
- `1 / 0`：影子一致1条、差异0条。
